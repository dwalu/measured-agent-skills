# Work Queue

**What to do next, in order.** Every open task in [`flows/`](flows/), sorted by rank.

Order comes from `**Rank:**`, not from TODO numbers. The two are different things:

- **`TODO-<n>` is identity.** Cited in commit messages, design docs and source
  comments, so it can never be renumbered — which is exactly why it cannot also
  carry priority.
- **`Rank` is order.** Nothing cites it, so it can be rewritten freely. Lower
  runs first; gaps of 100 leave room to insert.

Set a rank on the feature (`- **Rank:** 300` under the heading, covering every
task in it) or inline on one task to override. Precedence is
**task → feature → flow → unranked**.

Ties are legal and mean "the order between these does not matter". They break on
`(rank, file, line)` — so if the order *does* matter, give the tasks distinct
ranks rather than relying on where they sit in the file.

See [`README.md`](README.md) for the full conventions and the status legend.
